## Target architecture and first coding task

**Trusted shell, separate content sites, trusted HTTP credential handling.** Give every canonical upstream origin in a temporary workspace a distinct browser origin. Keep shell cookies, route allocation, provider consent, and relay approval on the shell site. Treat the entire destination origin, including any co-located bridge or injected reader, as untrusted. A message from that origin can supply text for an authorized answer or propose navigation. It cannot authorize an operation, select credentials, mint a general relay ticket, or attest that text is truthful.

Implement a proposed `isolation/origin-registry.mjs` and its unit tests first. Use an in-memory bidirectional map with these contracts:

- `allocate(workspace, upstreamURL)` returns an opaque, high-entropy route ID, exact content origin and canonical upstream origin. Same active workspace plus same canonical origin reuses the route. Distinct workspaces or canonical origins get distinct routes. Do not encode the destination or workspace in the hostname.
- `resolveHost(normalizedAuthority)` matches one exact active entry. Resolve only provisioned server-side records. A decoded path, forwarded host, referrer, or requested Origin must never create a mapping or change its upstream. Reject unknown, revoked, ambiguous and wrong-port authorities before content is served.
- `authorize(workspace, routeID)` and `revokeWorkspace(workspace)` enforce ownership, a finite idle/absolute lifetime, and bounded allocation. Normalize with `URL`, enforce HTTP(S), reject credentials, IP literals and forbidden ports, and retain every Stage 1 private-network rule. Keep scheme, normalized host and effective port distinct. Do not reuse expired physical hostnames.
- Test normalization, mismatched Host and SNI at ingress, collision handling, concurrent allocation, explicit expiry, quota, restart with stale browser URLs, DNS rebinding and blocked private targets. Route IDs identify routes. Authorization for sensitive actions still needs the correct session and operation scope.

### DNS and TLS prerequisites

- Bind the application and local ingress to loopback. Configure a trusted local test CA and resolver for a separate shell hostname and the content namespace. Verify normal certificates and genuine secure contexts in Safari and the in-app browser. Keep private keys outside Git and any public root. Retain the existing local profile. Use disposable browser profiles for migration tests.
- Distinct ports provide a DOM/worker boundary but do not separate browser cookies. Distinct hosts under an ordinary shared registrable domain still permit attempts to set parent-domain cookies. For a finite local pilot use separate registrable test domains. For arbitrary hosts require a browser-recognized public suffix boundary or an equivalent distinct-site design. Verify this in both browsers, including parent Domain cookie attempts, `document.domain`, and cross-site cookie behavior. Local DNS and a wildcard certificate alone do not provide that boundary.
- Provide a certificate covering each allocated content hostname at the correct label depth. Validate SNI and Host consistently. Configure HTTPS and WSS end-to-end from the browser. Avoid certificate interstitial bypass, broad trusted-proxy settings, and assumptions about Safari wildcard localhost support. Keep shell cookies host-only with Secure, HttpOnly and appropriate SameSite settings. Use host-only paths and verify any prefix requirements before changing existing cookie names. Content listeners expose no shell, AI, Admin, or operator API. Do not add public hosting configuration during the local migration.

### Navigation and credential decisions

- Treat each redirect hop as a new destination decision, using the real upstream Location resolved against the response URL. Same-origin hops can stay on their runtime. Cross-origin document hops must switch to the allocated content origin before document commit. Maintain network and navigation semantics for 301/302/303 and 307/308. Block an unimplemented cross-origin body handoff with a recoverable error. Preserve cancellation and never retry non-idempotent requests by copying their bodies. Validate nested-frame, open/target, referrer, and resource paths independently. If rewriting cannot place a document safely, block it. Do not render it on the initiator's content origin.
- Pin every HTTP dial to validated public DNS answers and recheck redirects. Reconstruct upstream Origin/Referer and credential mode from trusted request context, and apply browser-equivalent CORS and SameSite decisions. Reject ambiguous credentials. Browser denial of response reads alone does not prevent CSRF. Test actual request headers and upstream observations, as well as browser-visible results.
- The current libcurl WASM path runs HTTP/TLS inside the browser and Wisp carries raw bytes. The TCP relay cannot reliably enforce application-layer Host, credential, or redirect semantics inside that TLS. Use a trusted HTTP client/broker for authenticated HTTP and require scoped WebSocket endpoints that enforce upstream authority or a brokered handshake. Do not ship a raw TCP route that lets content choose unrelated destinations or forward arbitrary `Authorization`/`Cookie` values. Keep the Stage 1 DNS, quota, WebSocket pending-pong and one-use ticket safeguards. Exclude ticket query strings and credential material from logs.

## Implementation order and acceptance gates

1. **Ingress and allocation.** Add the registry and local HTTPS proof first. Exercise a separate shell plus two content sites and two simultaneous workspaces. Verify exact Host/route admission, wrong-host and wrong-workspace denial, cookie boundary even for sibling names, distinct storage/worker scopes, secure contexts and no new public listener. Extend the existing actual-proxy proof instead of substituting a native iframe-only test.
2. **Credential and egress boundary.** Implement the trusted broker, strip HttpOnly from bootstrap and bind relay/HTTP credentials and lifetime. Run malicious fixture tests for foreign cookies, stolen/expired/replayed or wrong-route tickets, raw Host/SNI substitution, mixed DNS, redirects to private networks, unsafe workers and privileged shell paths. Use synthetic canaries and inspect redacted upstream headers. Leave production controls in place when injecting exact synthetic test sockets.
3. **Mount isolated browsing in the real shell behind an explicit local opt-in, initially for the two fixtures.** Wire allocation, commit, and tab handoff for links, forms, redirects, nested documents and back/forward. Test click, location assignment, real cross-site redirect, same-site reload, 307/308 request handling, arbitrary iframe/popup attempts, cross-origin fetch, and WebSocket reconnect. Reject stale commit/evidence messages during tab switches. Expand the allowlist only after the two-site flow passes.
4. **Restore feature parity in isolated mode.** Test Google, DuckDuckGo, Wikipedia and a plain page in Safari and the in-app browser. Observe visible render, refresh, link and history behavior, Wisp reconnect, and worker recovery. Use one actual authorized Gemini page question and follow-up per needed scenario. Verify opt-out, wrong-origin, post-navigation and stale-response rejection. Confirm temporary cleanup over outer reload, tab close, server restart and expired/crashed workspace, without requiring profile deletion. Use existing Admin/Arcade automated coverage and check the 35-entry catalog and file preservation. Keep the existing AI provider, Admin IPC, telemetry and game origins outside the migration.
5. **Promote only after all local gates pass.** Retain a separate launch mode while validating. An isolated-mode error remains in isolated mode and fails closed. Run `node scripts/sync-runtime.mjs`, `npm run check`, `npm test`, and `git diff --check` on the final integration. Reuse existing Safari timing evidence unless the broker introduces an observed slowdown requiring a narrow cold/warm comparison. Native origin proof must pass through the normal shell before the shared-origin blocker can be closed. Public hosting and independent public-beta approval are outside this plan.
